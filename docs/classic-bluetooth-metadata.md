# 经典蓝牙车机的歌词与歌曲信息显示修复

## 现象

同一份媒体会话，智能互联车机（HiCar / CarLink / Android Auto）一切正常，但纯蓝牙
（A2DP/AVRCP）车机只显示部分信息，或者根本不显示歌词。自定义布局里已经配置了歌词
行，车机上却看不到。

## 根因

纯蓝牙车机读的是 Android 媒体会话的 `TITLE` / `ARTIST` / `ALBUM`（以及媒体通知的
`displayTitle` / `displaySubtitle`），它对「什么时候发、item 是不是同一首」比智能
互联协议敏感得多。当前代码里有四处会让自定义布局在这条链路上失效：

1. **自定义布局的歌词字段仍被旧的「广播歌词」开关控制。**
   `composeCarDisplayLines` 的 `lyricsEnabled` 直接取 `controlCenterLyricsNotifier`。
   这个开关本来是为旧的「把歌词塞进 title」行为准备的；新版布局里用户已经在某一行
   放了「原词 / 翻译」，却还要另开一个开关，否则该行的值被清空、回退成歌名。

2. **歌词刷新也被同一个开关挡住。**
   `_updateCurrentLyricIndex` 只有在 `controlCenterLyrics` 为真时才重新发布 item。
   开关关着时，即使布局里有歌词字段，第一次发布后也不会再跟随播放进度更新。

3. **经典蓝牙路由给 media id 加了自增后缀。**
   `updateServiceMediaItem` 在经典蓝牙路由下发布 `歌曲id#序号`。AVRCP 把新的 media
   id 当成「另一首歌」，而媒体会话的浏览队列仍用 `歌曲id`，两边对不上；部分车机因此
   不再稳定显示。

4. **浏览队列会盖住当前项。**
   媒体会话发布的 60 首队列窗口里，当前项是用普通字段构造的（标题 / 艺术家 / 专辑，
   没有当前歌词行）。有的车机读队列项而不是会话项，就只显示歌名和艺术家。

另外，默认布局只有两行（歌词 / `艺术家 - 歌名`），专辑本来就不会出现；这是布局的
选择，不是 bug，想要专辑把布局改成三行即可。

## 修复

所有修复都作用在现有自定义布局上，没有引入第二套固定映射，也没有新增必须手动打开
的开关。

### 1. 自定义布局自带歌词开关

`lib/base/data/car_display.dart` 新增：

- `carLayoutUsesLyrics(config)`：布局实际显示的行里是否有「原词 / 翻译」字段。
- `carLyricsEnabled(config, legacySwitch, classicRoute)`：
  - 布局里没有歌词字段 → 不取歌词；
  - 经典蓝牙路由且布局含歌词字段 → **始终取歌词**，不再依赖旧开关；
  - 智能互联路由：用户自定义过且含歌词字段 → 始终取歌词；布局仍是未改动的默认值
    → 保持旧开关语义，避免改变现有智能互联设置。

`updateServiceMediaItem`、`_updateCurrentLyricIndex`、`refreshServiceMediaItem` 都改为
使用这个统一判断。于是：只要你在「歌曲广播 → 布局」里放了歌词字段，经典蓝牙一定按
布局显示并跟随进度更新；智能互联在自定义布局下同样如此，默认布局则保持原样。

### 2. 稳定 media id

`updateServiceMediaItem` 不再生成 `歌曲id#序号`，整首歌始终使用 `currentSong.id`。
会话项和队列项指向同一个 id。

### 3. 经典蓝牙的发布节奏

保留并沿用已有的路由检测（`_classicBluetooth`）：

- 歌词变化时 `force` 直接写 item，绕过合并/去重/最小间隔；
- 写完 60ms 补一次 `PlaybackState`，让只认状态事件的旧车机重读；
- 切歌后按 0 / 450ms / 2s 再补发当前项，覆盖「会话刚激活时车机读不到」的情况。

### 4. 经典蓝牙不发布浏览队列

`_publishQueueWindow` 在经典蓝牙路由下直接返回，并把已经发布过的队列清空一次；
智能互联路由照常发布。这样车机只会读当前项的会话元数据，也就是带歌词的那一份。
路由从蓝牙切回智能互联时会重新发布当前项，队列也随之恢复。

### 5. 「经典蓝牙广播」开关（手动兜底）

设置 → 歌曲广播 顶部新增「经典蓝牙广播」开关：

- **关闭（默认，自适应）**：根据当前音频输出自动选择。检测到经典蓝牙（A2DP/SCO）
  时使用上面的经典发布方式；智能互联则保持原逻辑。
- **打开（强制）**：无论当前输出是什么，都使用经典蓝牙的发布方式，包括稳定 id、
  直接发布、不发布浏览队列和经典三行映射。用于车机没有把音频路由上报为蓝牙的情况。

布局仍是唯一文本来源：用户自定义过的布局按配置原样发布；只有未改动的默认布局在
经典模式下使用固定的三行映射（歌词 / `艺术家 - 歌名` / 专辑），歌词放在主行还是
副行由「广播歌词」开关决定。

### 6. 经典蓝牙封面（同一套自适应/强制逻辑）

经典蓝牙封面也跟随「经典蓝牙广播」开关和路由检测：

- **自适应/强制时生效**：检测到经典蓝牙（或开关打开）时使用「经典蓝牙封面」选中的
  方案；智能互联路由仍按原来的「封面广播」模式，不受影响。
- 默认方案是 **完整方案**：
  - `artUri`：本地封面文件（`file://`）；
  - `DISPLAY_ICON_URI` / `ALBUM_ART_URI`：流媒体源用服务器直链（认证在 query 里），
    本地/WebDAV 用手机局域网中继，最后兜底 `content://`；
  - `artCacheFile`：100px 广播位图。
- 仍可切回「位图 / 位图 + URI / 原始大图 / 位图 + 中继 URI」逐项排查兼容性。
- 旧版本存下的默认值 `bitmap` 会一次性迁移到完整方案；如果之前手动选过其它方案，
  会保留原选择。

## 验证

1. 在「歌曲广播 → 布局」里配置至少一行「原词」或「翻译」；歌词开关可以保持关闭。
2. 连纯蓝牙车机播放带时间轴歌词的歌曲。
3. 日志（`adb logcat | grep '\[media\]'`）应出现：
   - `lyric index ... broadcast=true ...`
   - `publish id=<歌曲id> kind=lyric ... lines="..." | "..."`
4. 车机应显示布局配置的文本，并随播放进度更新歌词行。
5. 切回智能互联车机：默认布局且歌词开关关闭时，行为与修改前一致；自定义布局且含
   歌词字段时，歌词会按布局正常广播。

## 如果仍然不行

先把「经典蓝牙广播」开关打开再试一次；它跳过路由检测，强制走经典发布方式。如果
仍然不显示，抓 `[media]` 日志（包含 `publish ... lines=...`）再定位车机实际读的是
哪个字段。
